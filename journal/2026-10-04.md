### 18:50 — fix: getupdates 改为 ack 驱动投递（at-least-once），溢出改背压（issue #27）

- 投递语义：`MessageQueue::drain(vtoken)`（破坏性读取）→ `MessageQueue::poll(vtoken, ack: Option<u64>) -> PollBatch { msgs, cursor }`；只有被 ack 覆盖的前缀被移除，无 ack 时整批重投（响应回程丢失不再丢消息）
- 稳定投递 id：Hub 入队时给每条消息分配 per-vtoken 单调 `WeixinMessage.seq`（从 1 起），重投保持同一 id，下游按 id 去重
- 溢出策略：队列满时**拒绝新消息**（保留最旧），不再静默丢最旧；`push` 的 `Ok(true)` 语义就是该背压信号
- `getupdates`：响应 `get_updates_buf` 恒为本 vtoken 的投递水位（非空十进制）；请求侧新增 `GetUpdatesRequest::ack_watermark()`，取 `get_updates_buf`（十进制）与新增 `last_ack_id` 的较大值，空串/非十进制/负数视为未 ack；ack 被钳制到已分配的最大 id（伪造大游标既不吞掉未分配消息、也不静默后续消息）
- 可观测：新增 `ilink_hub_messages_rejected_total{client=…}`（per-client 背压拒绝归因）；`ilink_hub_messages_dropped_total` 语义收敛为 Hub 级总量（背压拒绝 + push 错误）；`queue_sizes()` 改计未确认消息数
- 停机：`drain_queues_before_shutdown` 从「等队列排空」改为「等已投递批次被客户端 ack」，`ILINK_SHUTDOWN_DRAIN_SECS`（默认 30s）仍是超时兜底
- 并发语义：同一 vtoken 多个 poller 不再互相「偷」消息，而是各自收到同一批（重复投递、先 ack 者先退休）；`state.rs` / `routes/bot.rs` 的 split-brain 告警与注释随之改写
- 测试：新增 `tests/delivery_ack.rs`（12 条验收用例：稳定 id、丢响应后重投、游标续拉、防重投、背压归因、伪造游标钳制、客户端重启后游标存活）→ `12 passed`；`tests/queue_concurrency.rs` 按新语义重写（原「同 slot 4 consumer 不重不丢」不变量与 at-least-once 直接冲突，改为 per-client 扇出：client 内不重不丢、跨 client 无串扰、全部 ack 后 `queue_sizes` 归零）；`queue_trait_tests` / `hub_routing_integration` / `e2e_wechat_simulation`（harness 改为逐轮回带游标）同步改写

### 20:32 — feat(hub)!: 授权可吊销 —— active_sessions TTL、revoke 端点、A2A 单次授权与微信白名单 (#26)

- 根因：授权不是显式记录，而是「`active_sessions` / `backend_sessions_v2` / `messages` 三表 OR 存在即通过」派生，且三表只增不删（无 TTL、无 revoke）→ 派发即写永久授权；A2A（`call_agent` 把调用方 vctx 授给目标 vtoken）把它升级为跨租户永久写通道
- 迁移 v15：`active_sessions` 加 `expires_at`（epoch 秒，`DEFAULT 0` = 存量行 fail-closed）；`ILINK_GRANT_TTL_SECS`（默认 86400）由派发 / 广播 / A2A 每次写入刷新，读侧（`resolve_send_context` / `vtoken_owns_vctx` / `get_active_ctx_for_vtoken`）一律要求 `expires_at > now`
- 新增 admin 端点 `POST /hub/clients/{name}/revoke`：轮换 vtoken + 清空旧 hash 的三表授权行 / 路由 / 队列 / `last_seen`。**顺序是正确性关键**：先 `revoke_authorizations_for_vtoken(old)` 再 `upsert_client(new)`，否则 `upsert_client` 的 routing_state 迁移会把已吊销的路由复活
- 归属判定删除 `messages` 分支：历史记录不再构成发送授权（`src/store/context.rs` 两处谓词同步）
- A2A：授权行 scope = `a2a-<call_id>`，回复 / 超时 / 断连三条出口都回收；`backend_sessions_v2` 按**调用前快照的差集**回收（目标可自选回带的 session 名，只删 `reply_session` 会留下无 TTL 的永久授权行）；调用前已有授权按快照恢复
- A2A ACL + 微信可见集合：新增 `ILINK_AGENT_ALLOWLIST`（`caller->target` / `user:<uid>->backend` / 裸 `backend` / `*`，非法条目 warn 跳过）。A2A **默认拒绝**（ANY 副作用之前）；微信 `/list` `/use` `/status` `/broadcast` `@name` 共用同一可见集合，序号按可见集合重排
- 测试：`tests/issue26_authorization.rs` 9 条（revoke 轮换 / 历史不成授权 / A2A 回复·超时·断连三出口回收 / 差集回收（含对照）/ 拒绝无副作用 / `list_agents` 只列可见）+ `tests/e2e_wechat_simulation.rs` 2 条（`/list` `/use` 白名单收敛 + `@name` 不可达）+ `store_tests` 三表清理断言
- 已知残余：微信粘性路由不受可见集合约束（`routing_state` 跨重启存活）；`backend_sessions_v2` 无 TTL；abort 时 A2A 授权行残留；A2A 释放恢复 `prev_active` 时经 `set_active_session_with_depth` 顺带刷新该 pair 的 `expires_at`（续一个新窗口，仍受 `ILINK_GRANT_TTL_SECS` 约束）；引用回复仅凭历史授权的路径会 403
